# Agent Note: 第三方包导入适配规范与缺失补齐

Status: proposed

## 问题

第三方包的 `autolib-import.cmake` 在排版、发现方式、变量命名和职责组织上不一致。原有 31 个配方版本只有 24 份 adapter，缺少自身或依赖 adapter 的包不能通过统一入口消费。需要统一当前全部配方版本的导入方式和格式，并为后续作者提供独立于真实库的编写参考；文件存在或配置成功不能代替真实消费验证。

## 方案

### 范围与归属

在当前普通任务分支内单阶段统一全部 31 个配方版本，包括 Eigen 3.4.0 和 5.0.1，并完成原缺失的 freetype 2.13.2、harfbuzz 8.5.0、onnxruntime 1.24.4、libusb 1.0.27、nlohmann 3.12.0、opencv 4.14.0、librealsense 2.58.1 七份 adapter。已制作的代表 adapter 纳入同一集合核对，不重复作为独立阶段验收。

不引入 GStreamer、libudev 或其他新模块，不升级版本、不恢复 sherpa-onnx。现有 adapter 可以按本设计改变发现方式、删除多余检查并修正旧 sibling 消费接线，不要求保持旧发现行为；公共包身份、版本、所支持的功能和单一公共目标不变。不修改配方来源、编译选项、第三方补丁、根入口、builder、importer、打包引擎或 CI 资格规则。

[当前架构](../../../architecture.md)与[版本化交付设计](2026-10-29-versioned-artifact-delivery.md)继续拥有安装布局、精确依赖、包头、缓存和消费入口。[分批迁移](2026-10-28-batch-module-migration.md)、[RSUSB 构建](../../implemented/architecture/2026-10-27-librealsense-rsusb.md)和[平台输入迁入](../../implemented/architecture/2026-10-20-local-reuse-and-platform-inputs.md)继续拥有来源、构建选项、系统依赖及既有验证；本设计只承接其未覆盖的下游适配。

### 五类导入方式

五类完整格式、示例和新增步骤由[模块 skill 参考](../../../../.agents/skills/add-third-party-module/references/adapter-baselines.md)拥有。示例统一使用虚构 `sample`，存放在 skill 的 `references/`，不绑定真实库、不放在 `example/`，也不为填满分类新增模块。

选型顺序为：下游只需要头文件时直接包含，即使库提供 Config；需要链接且有可用 CMake Config 时使用 Config；没有 Config 时，CMake Module 与 pkg-config 平级，按实际平台支持、依赖表达完整性及手工补充负担选择一种；均无合适方式才使用 `find_library`。Module 与 Config 使用独立基准，不因两者都调用 `find_package` 而合并。每个 adapter 固定选择方式，不添加自动回退链。

只设置优先搜索位置，不增加包内产物来源核验、搜索隔离、`NO_DEFAULT_PATH`、目录或载荷存在性预检查。标准发现命令使用 `REQUIRED`。这不承诺搜索结果必须来自本包；验证时核对实际命中位置，不为该核对增加消费端复杂代码。

### 共同结构与消费边界

只读参考 `D:/Work/AutoLibBuilder/src/dependencies/*.cmake` 开头注释中的消费示例，借鉴用途说明和配置组织，不复制旧安装路径、全局链接列表、库目录扫描或直接操作下游目标的写法。参考仓库及上游源码保持不变。

源码 adapter 以简短中文块注释说明用途、导入方式、`autolib::<name>` 以及必要的消费限制。包身份、版本、平台和精确依赖由 builder 写入安装副本的固定五行头，正文不重复维护或改写生成头。

正文保留公共目标 guard、必要发现和上游目标处理、唯一公共目标及其使用要求；不适用的段落省略。每包只建立一个全局 `INTERFACE IMPORTED` 公共目标，不保留大写兼容别名。纯头文件直接设置包含目录，保留必要编译标准、宏和传递依赖；上游导入目标按实际导出关系处理跨目录可见性，不为统一外观扫描所有目标或 Config。

命令小写、四空格缩进，路径参数加引号且保留 CMake 列表语义。私有变量采用 `_autolib_<包名片段>_<用途>`，包名片段将 `-` 替换为 `_`；上游变量和目标保持原名。短命令保持一行，仅长参数或列表按阅读需要换行；逻辑段之间留一个空行，不增加逐行解释、空标题或装饰分隔。

直接包依赖沿用 `module.toml` 的 `depends`。入口准备精确闭包并按依赖顺序加载，adapter 链接相应 `autolib::<dependency>`；需要依赖目录时使用 `AUTOLIB_PACKAGE_DIR_<name>` 和版本信息，不推断 sibling 目录、不重选 latest、不递归加载依赖 adapter。系统 Threads、udev、OpenMP 等按实际产物保留，不将静态库等同于自包含。

公共目标封装包支持的库和声明依赖，不聚合互斥静动态产物，也不把某个应用的可选组件列表固化成所有下游的共同依赖。不增加组件选择 API、兼容目标、下载、编译、自修复或载荷复制机制。动态库及必要运行文件由现有安装、打包机制交付。

### 缺失 adapter 的包级要求

| 包 | 必须保留的消费能力 |
| --- | --- |
| freetype 2.13.2 | 按实际安装的 Config 导入字体引擎及其导出依赖。 |
| harfbuzz 8.5.0 | 按五类规则选择实际安装提供的方式，传递 `autolib::freetype`。 |
| onnxruntime 1.24.4 | 导入官方 CPU 归档头文件、共享库或 Windows 导入库，说明运行库加载要求。 |
| libusb 1.0.27 | 封装实际静态库，保留 Linux udev、线程及 Windows 系统库要求。 |
| nlohmann 3.12.0 | 直接暴露安装头文件，不使用 Config 或查找二进制库。 |
| opencv 4.14.0 | 使用实际 OpenCV Config，保留 world/contrib 及文字绘制能力，传递 FreeType、HarfBuzz 依赖。 |
| librealsense 2.58.1 | 使用 realsense2 Config，保留共享 SDK、RSUSB 和 JSON、LZ4、libusb 直接依赖。 |

具体目录、库名和上游目标按实际安装核对，不以基准假定布局替代事实。需要修改配方、第三方构建、公共引擎或既定功能才能消费时，暂停受影响工作并报告证据及最小下一步，不借规范化扩大实现范围。

### 单阶段交付与文档

一次完成现有 adapter 统一、缺失项补齐、相关消费验证和文档更新，统一验收，不保留“先只改格式、再补缺失”的阶段交接。内部任务按可独立验证的包集合组织，不新增后续阶段。

模块 skill 拥有五类基准和后续编写步骤；[开发指南](../../../development.md)链接该入口并说明实际操作，[测试指南](../../../testing.md)拥有验证命令及覆盖范围，[路线图](../../../roadmap.md)记录已完成范围。普通文档只陈述已落地事实，不复制完整基准或提前宣称全部包可消费。计划、检查清单和过程证据保存在忽略的 `.superpowers/`，不新增生成器、公共 helper、资格数据库或每库测试框架。

### 验证与操作范围

本机只编辑、只读核对和运行不隐式编译的文档及 skill 校验。Go、C/C++ 编译、adapter 执行和实际消费仅在[授权 109 目录](../../../development.md#远端构建与源码传输授权)进行，不使用其他机器、不验证最低 CMake、不下载旧工具。传输前逐文件核对摘要，使用隔离任务目录，保留未知差异及无关数据，不传项目 `.git/`、凭据、SDK、缓存或宿主产物。

格式和同目录覆盖检查覆盖全部 31 个版本；按行为变化选择定向回归，不把每种排版规则写成测试，不运行全量 Go test/vet 或重编无关库。重复导入、跨目录目标可见性、实际发现和传递依赖使用最小有意义的消费者验证；没有被修改影响的现有证据直接复用。

七个原缺失包必须通过公共 `autolib_import` 消费，编译链接最小真实消费者，动态库运行验证加载位置；不能以直接 `find_package`、文件存在性检查、空库或合成 Config 代替真实包消费。沿用现有消费者机制，必要时补充 smoke。OpenCV 不扩展算法验证，librealsense 只进行无相机对象和接口检查，ONNX Runtime 只调用运行库 API，不下载模型或执行推理。两个 Eigen 版本使用独立消费者。

优先复用已核对版本、配置和完整性的安装。缺少所需产物时先报告具体缺项和最小准备范围，不擅自重编全部库、覆盖未知安装或更改配方。正常根入口的复用构建负责刷新 adapter，不手改生产安装描述，不把 sentinel 或 stamp 当作消费成功证据。

使用现有 builder 对受影响集合和依赖打包，在新的隔离目录解包，通过同根入口重新消费、链接和运行，核对不依赖生产前缀；原安装保持不变。发现命令不隔离系统搜索，因此需观察实际链接输入，防止系统包掩盖缺失产物。缺依赖及身份错配等入口错误复用已有定向证据，不增加全面故障注入或平台组合矩阵。

本轮原生实测平台为 109 的 Linux x86_64；Windows x86_64、Linux aarch64 的配方及路径分支静态核对，真实构建消费由用户手动 CI 验收，不记为通过。新增 adapter 会按现有 CI 规则扩大可选根及严格 `all` 集合，不增加白名单或跳过掩盖未验证包。

本设计范围包含本地提交及上述 109 源码传输和验证，不含 push、远端 CI、发布或远端合并。设计作为当前任务分支首提交，后续修订留在该分支，不创建 worktree、不改写历史。实施计划保存在 `.superpowers/plans/`，推荐本会话直接执行，结束后一次独立整体审查。

## 备选方案

**保持行为的格式整理与缺失补齐分两阶段。** 能单独验收纯排版，但统一发现方式已属于本次目标，且五类基准已确定。分阶段会重复处理相同 adapter 和规范，因此采用单阶段、一次整体验收。

**只整理现有 adapter，缺失项按需补齐。** 维护成本较低，但不满足当前全部 31 个版本具备 adapter 的目标；未来纯本地构建配方仍可不提供 adapter，不因此扩大后续每个模块的交付义务。

**以真实库或新接入库充当五类永久基准。** 容易把包特有布局、平台供应和应用组件组合误写为通用规则。使用 skill 内虚构示例，不新增 GStreamer 或其他模块，不把示例混入真实下游工程。

**严格限定包内搜索并预检查所有载荷。** 可以更早发现部分错误，但引入重复检查和结果核验。采用优先搜索位置和标准失败机制，将命中位置核对放在验证中，不承诺严格隔离。

## 验收标准

全部 31 个配方版本有同目录 adapter，遵循已确认的五类选型及共同格式，公共目标和依赖完整；原七份缺失项通过 109 真实消费者编译链接，动态库最小运行及隔离打包搬迁通过。版本、功能、原安装和无关数据不变。

skill 参考和入口、开发及测试文档一致，文档、Agent Note、skill 校验及相关定向回归通过。交付区分格式检查、合成夹具、真实消费和平台缺口，不将文件齐全、配置成功或静态核对写成真实发行通过。某包因缺少产物或需要越界修改未完成时如实报告，不用空 adapter 代替完成。

## 风险

各包的 Config、Module、静态传递依赖、可选功能及平台布局仍需逐包核对；统一格式不是纯文本替换。优先搜索并不排除命中系统库，实际链接输入是必要验证证据。

补齐 adapter 会扩大后续 CI 的工作量，Linux x86_64 证据不替代 Windows、Linux aarch64、相机取流、模型推理或跨工具链 ABI 验证。真实产物不足时可能需要用户决定最小准备范围，不为完成数量而改变构建或增加通用机制。

## 验证结果

109 Linux x86_64（GCC 9.4、CMake 3.31.12、Make 4.4.1）在 `/home/lxx/xxautolib/build/adapter-standardization-pEUrq7gz/real/` 完成八包正常根构建：三个根为 OpenCV、RealSense、ONNX Runtime，依赖为 FreeType、HarfBuzz、libusb、nlohmann、LZ4。输入先在 Windows 获取校验，Git bundle 在隔离源码中固定提交；不修改配方、选项或上游补丁。OpenCV 的 NASM 对 `.note.gnu.property` 发出 unknown section attribute 警告，构建退出 0。

HarfBuzz 8.5.0 的实际 Config 将包含目录导出为 `/harfbuzz`，使公共入口消费在 generate 阶段失败；其 `.pc` 路径正确，adapter 使用 pkg-config 并补齐 FreeType 与 Threads。ONNX Runtime Linux x64 官方归档的 Config 引用 `lib64` 和 `include/onnxruntime`，与实际 `lib`、`include` 布局不符，不能直接使用；adapter 保留显式查找。两者均未通过修改安装元数据掩盖问题。

既有 `tests/autolib/run-installed.cmake` 的原安装消费 `run-c384ce5517f50a66`、builder 原生打包后独立解包的消费 `run-225572a52d6eeeb7` 各通过 1/1 CTest，运行七包真实 API。三个共享库均从相应安装根或搬迁根加载，ONNX Runtime 报告版本 1.24.4。搬迁消费者的导入属性、链接输入和真实链接命令无原安装前缀，原安装普通文件摘要核对一致。子目录首次导入后，父目录和兄弟消费者另通过 3/3。

独立负样本副本移走七份新增 adapter 后，七个公共入口请求分别因所选描述不存在而失败。31/31 同目录覆盖及十九项受控发现检查不等同于真实第三方消费。两个 Eigen 版本各有 9/9 受控头文件检查，尚无本轮真实 Eigen API 消费证据；Windows x86_64、Linux aarch64、最低 CMake、模型推理和相机取流未实测。
