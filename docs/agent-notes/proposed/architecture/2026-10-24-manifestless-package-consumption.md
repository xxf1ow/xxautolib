# Agent Note: 无全局清单的双来源包消费

Status: proposed

## 问题

固定 Release 的包可以独立更新，但共享可变发行清单要求每次发布重新提交其他包的记录。替换清单时丢失旧文件，会使局部重跑缺少恢复未选包记录的依据。为此增加清单备份、回滚或历史版本选择，会扩大个人使用场景的维护成本。

消费者实际需要的是用户请求的包、每个包的直接依赖，以及取得当前产物的方法。要求用户列出完整依赖闭包或手动额外下载摘要文件，会把工具可以完成的工作交给用户。

## 方案

消费者使用可选的本地根和远端来源，按固定顺序获取包；包携带自身身份和直接依赖，不维护全局 `manifest.json`、版本目录、锁文件或历史选择规则。每个 `(name, os, arch)` 仍只有一个当前槽位，平台无关包使用成对的 any/any。消费端遍历名称依赖，不做版本约束求解，也不承诺不同更新批次的 ABI 兼容或整套发行快照。

本文拥有双来源查找、包内消费依赖、无清单发现和损坏检测，部分替代[固定槽交付设计](2026-10-20-name-only-artifact-delivery.md)与[Go 工具层设计](2026-10-21-go-tooling-and-offline-import.md)中的单一来源、统一清单及调用者列全包规则。两份记录继续拥有可搬迁打包、adapter、纯 Go 工具和平台运行约束，并保留历史离线接口的验证基线。[CI 系统设计](../../implemented/architecture/2026-10-20-ci-system.md)独立拥有生产身份、上传、缓存和运行汇总。

### 来源与查找顺序

入口分别接收 `LOCAL_ROOT`、`REMOTE_ROOT` 和用户请求的根包名；两个来源分别可省略，不同时省略。一次调用只处理一个目标 OS/架构，目标平台、工作目录和结果位置继续显式传给 importer，不由包内代码改变。CMake 使用 `autolib_import(LOCAL_ROOT <目录> REMOTE_ROOT <Release地址> PACKAGES <根包...> [WORK_ROOT <目录>] [TARGET_OS <os>] [TARGET_ARCH <arch>])`，其中两个来源关键字按需省略。CLI 使用 `prepare`、可选 `--local-root`、`--remote-root`，必填 `--work-root`、`--os`、`--arch`、`--result` 及至少一个可重复的 `--package`。显式空来源、空包名、未知参数及位置参数失败；根包重复保留首次出现。旧 `URI`、`--uri`、`--manifest` 明确报错，不维护两套入口兼容层。

对根包及其每个依赖，消费者使用同一顺序：本地已解包包目录、本地固定名归档、远端固定槽资产。未配置本地根时跳过前两项；未配置远端来源时不发起任何远端请求。所有请求及依赖已在本地就绪时，即使配置远端也不查询资产或检查更新。

查找只使用约定布局和完整包名，不递归扫描任意安装树，也不从 CMake Config 猜包名。只有候选不存在才能进入下一查找层；已存在的候选若身份不符、文件类型错误、归档损坏或读取失败，立即报错。同一查找层同时存在本包的 any/any 与当前目标平台归档时拒绝歧义，不在二者之间设回退优先级；远端资产层使用相同规则。已经选中的包目录不再检查被其遮蔽的归档或远端，其他目标平台的准备目录及归档不参与本次冲突判定。

本地根用于存放并复用已准备包和归档，缺包时也是准备结果的写入位置。最终包采用共同的目标平台父目录，使声明为 sibling 的依赖保持既有可搬迁布局；获取到的缺包只创建尚不存在的包目录，不覆盖、删除或原地修正已有包。已解包包优先于同槽归档，因此更新归档不会自动刷新已有目录，刷新仍由用户显式移除相应包目录。

本地根的归档与 importer 放在根下，准备包放在 `packages/<目标OS>-<目标架构>/<包名>/`；通用包的归档名及包内身份仍为 any/any，准备位置与其机器码依赖共用当前目标平台目录，不按 publisher 分目录。同一通用归档可分别准备到多个目标平台目录，这些副本是合法复用，不是通用槽与平台槽冲突。例如：

```text
LOCAL_ROOT/
  autolib-importer-windows-x86_64.exe
  queue-any-any.tar.zst
  lz4-windows-x86_64.tar.zst
  flann-windows-x86_64.tar.zst
  packages/windows-x86_64/
    queue/autolib-import.cmake
    lz4/autolib-import.cmake
    flann/autolib-import.cmake
```

用户可以只放归档或按此布局放已解包目录，不要求两者同时存在。本地归档解包及远端补齐的缺包都进入该准备包目录；远端下载先在受控工作目录校验，不要求再持久化一份压缩包。已有已解包包不检查同槽归档或远端更新，身份冲突检查针对本次实际查找的候选，不额外扫描整个本地根。

未提供本地根时，下载和解包仍需使用受控工作目录交付本次结果，但不把它变成未声明的备用来源。需要后续跨运行复用时，用户显式指定本地根。多个独立构建不共享写入中的工作目录；向同一本地根写入由调用方串行安排，不支持多个 importer 并发准备同一共享根，不增加全局缓存锁或后台更新器。已有完整包可以并发只读复用，但不与写入交错。

实际工作根及最终包目录不得含分号；由于本地根也是准备包的父目录，该限制同样适用于本地根。相对本地根与工作根在 CMake 入口按顶层源码目录转为绝对路径，再按字面参数传递；直接 CLI 调用按当前目录解析。Windows 盘符和 UNC 保持文件系统路径语义，不做 URL 推断。

网络可用性由调用方安排。不配置远端参数保证本工具不联网；配置远端但网络不可达时，只有实际缺包才尝试并报告失败。不增加离线探测、隐含远端默认值、其他仓库搜索或自动镜像回退。

### 包内身份与依赖

builder 继续读取模块声明，打包时将本目标平台生效的直接包依赖写入包内 `autolib-import.cmake` 的固定数据头。名称、OS、架构和直接依赖只有一个包内所有者，不新增重复身份文件或发行总表。文件前四行严格依次为以下单行字面赋值，接受 LF 或 CRLF，不接受前置内容、缺行、字段换序、重复字段替代必需字段或 CMake 表达式：

```cmake
set(AUTOLIB_PACKAGE_NAME "flann")
set(AUTOLIB_OS "windows")
set(AUTOLIB_ARCH "x86_64")
set(AUTOLIB_DEPENDENCIES "lz4")
```

第四行值为空字符串或以分号分隔的完整包名，不含空项、空白、版本、URL、路径、工具安装命令或系统包。builder 对直接依赖按 ASCII 字典序排序去重；importer 对合法列表执行同样归一，重复依赖不是错误。前三行必须通过名称及平台校验；名称精确匹配请求，OS/架构精确匹配目标或成对为 any/any，半通用身份拒绝。adapter 正文不得另行维护或改写这四个字段，importer 不解析正文以发现另一套身份。

包名沿用 `^[A-Za-z0-9][A-Za-z0-9_.+\-]*$`，另拒绝末尾点及 Windows 保留文件名：取第一个点之前的名称、不区分 ASCII 大小写，拒绝 CON、PRN、AUX、NUL、COM1～COM9、LPT1～LPT9。同一请求依赖闭包中仅大小写不同的名称拒绝，保持所有宿主一致；不扫描无关包寻找冲突，不修改普通源码模块命名规则。此固定四行协议由 builder 与 importer 同步切换，旧三行包头拒绝，不增加格式版本、启动前查询或兼容协商。

importer 只解析固定数据头，不执行 CMake，不读取生产仓库的 TOML，也不维护每库适配表。依赖声明随已解包目录和归档一起搬运；仅给出 flann 时，消费者从包内声明取得 lz4，再使用相同来源顺序准备它。编译器、OpenMP 等系统运行要求不因此变成可下载的 AutoLib 包。

消费者按根包首次出现顺序进行深度优先遍历，每包先按来源顺序取得并校验数据头，再按归一后的直接依赖顺序递归；已经完成的共享节点不重复获取或输出。活动递归路径中再次遇到同名包即报依赖环，不再次获取该节点；环检测发生在获取过程中，不承诺获取前知道完整图。结果采用后序：依赖在前、使用方在后。例如根包为 `app;tool`，app 依赖 `beta;alpha`，alpha、beta、tool 均依赖 core，结果固定为 `core;alpha;beta;app;tool`。

它不要求知道发行源包含哪些其他模块，不扫描未请求包的依赖。全部根包及可达依赖准备完成后才写入本次完整结果；某包失败即停止遍历，不继续获取后续根包，不提交可加载结果，也不删除已经成功准备的其他包。包文件完成自身校验即可保留，不要求它的依赖闭包已经成功，下一次调用仍重新核对其数据头并准备缺失依赖。

adapter 仍只负责将已准备的本包及声明 sibling 接到真实导出 target，不联网、不编译源码、不回退系统同名库、不在消费时改写上游元数据。CMake 核对本次结果包含全部请求根包，并允许附带自动解析的依赖。首次导入同名 target 冲突、重复 include guard、实际包路径不含分号及字面路径编码等约束继续有效。

单文件入口的重复 include 不创建 target；同一次 configure 内的多次 `autolib_import` 固定使用同一规范化来源对、目标平台和工作根，后续调用可补充根包。切换这些输入须重新启动 configure，不能在同一进程混用。每次调用仅在当前 prepare 成功、完整结果核对通过后加载本次 adapter，不读取旧结果变量补齐；adapter 自身失败以 FATAL_ERROR 终止 configure，不承诺回滚已创建的 target。改变来源或平台不自动删除本地根已有包。

### 远端发现与信息复用

首个远端实现限定为用户明确指定的公开 GitHub Release，不承诺任意 HTTPS 目录能提供资产枚举和预期摘要。`REMOTE_ROOT` 使用 `https://github.com/<owner>/<repo>/releases/tag/<tag>`，tag 按 URL 路径编码；通过仓库及精确 tag 的 API 定位 Release，不解析 HTML，不发现 latest 或历史版本。只接受已发布、非草稿 Release；显式指定的 prerelease 也可消费，不依据该标志选择版本。私有或不可见 Release、删除、认证及其他 API 错误直接失败，不回退其他 Release，不要求消费 token。

消费者使用资产 API 取得完整分页、固定资产名、资产 ID、上传状态和 SHA256。包名为 `<name>-<os>-<arch>.tar.zst`；工具名为 `autolib-importer-<os>-<arch>`，Windows 加 `.exe`。对本次需要的固定名要求唯一候选；同名候选超过一个、状态不是 `uploaded` 或身份信息非法时失败，不依据 API 返回顺序选择。不校验或下载无关资产。名称定位候选，包内身份仍须核对，不能仅凭名称认定内容有效。

只有缺少 importer 或包时才读取远端资产信息。“同一次 configure”指一次 CMake 配置进程内的全部 AutoLib 调用；一轮枚举包括该 Release 的全部资产分页，不是只发一个 HTTP 请求。入口与 importer 通过本次受控临时 API 响应文件复用该轮信息；谁首次因缺失需要远端，谁完成枚举并使其可供后续调用复用，完整本地命中不枚举。直接调用 importer 时，范围为本次 prepare 进程。

临时响应文件仅保存本次指定仓库、tag、Release ID 及完整资产响应，由当前 configure 的独立工作目录持有；读取方核对来源匹配、响应结构及分页完整后使用，不以缺失或残缺文件表示空 Release。不同 configure 不共享这些文件；正常结束清理，异常残留不在下次复用，不生成另一份发布或消费清单，不维护跨运行 TTL 或离线资产目录数据库。

本轮对选中资产固定使用枚举取得的 ID 和摘要下载；删除、替换、不可下载、摘要不符或 API 错误均结束本次调用，不在同一轮自动重枚举或重试，用户显式重跑重新读取事实。该规则不提供多个资产在同一发行时刻的快照。

首次工具引导由单文件 CMake 入口完成，按宿主而非库目标平台选择 importer。已有本地工具继续复用；本地根中的对应宿主工具可直接取得，缺失时才按显式远端来源下载。联网下载在执行工具前核对 API 提供的 SHA256；本地工具作为用户提供的可信可执行输入，不以临时计算自身哈希冒充来源校验。工具缺失、不能执行或准备失败均明确失败，不回退 Go SDK、Python、builder 或系统同名程序。

CMake 引导和 importer 均校验证书，初始请求与资产重定向使用 HTTPS，拒绝降级。公开 Release 消费不要求用户配置发布 token，不将 CI 凭据、生产 build ID 或发布授权交给消费端。工具运行要求与库 ABI 分别验证，不因为工具可运行就视为库兼容。

### 单归档损坏检测

本地归档不要求外置 `.sha256` 或清单。builder 生成带内容校验和的 tar.zst，importer 完整读取压缩流并检查解码错误后才提交解包结果。校验值针对解码内容计算，不包含校验字段自身，因此没有整个归档摘要写回归档的自引用问题。它检测意外内容损坏，不等同于 SHA256 字节对照，也不提供发布者认证或恶意替换防护。

内容校验保证针对 builder 生成的归档；编码器显式启用校验，解码器不得忽略已有校验。多帧、可跳过帧及尾部处理沿用固定解码库：完整读流返回错误即拒绝，不另写 Zstd 解析器或强制单帧。其他工具生成的无校验帧不额外拒绝，但只能完成解码及包结构校验，不宣称具有相同损坏检测能力。

远端下载额外以资产 API 的有效 SHA256 对照实际字节：digest 必须是小写前缀 `sha256:` 后接恰好 64 位十六进制，十六进制大小写均接受、比较时归一；缺失、其他算法、非法格式、下载截断或不匹配均失败。已经解包的本地目录核对身份和依赖声明后复用，不逐文件重新散列，不承诺检测所有本地内容修改。不新增文件哈希树、签名、公钥分发或不可信代码沙箱。

安全解包规则继续由[Go 工具层设计](2026-10-21-go-tooling-and-offline-import.md#打包导入与发布)拥有，包括拒绝越界路径、类型冲突、外部链接和不需要的特殊文件。包完成全部校验后才移入最终目录；损坏包不自动覆盖已有缓存，也不以禁用校验绕过失败。

解包可以边解码边写入最终目录所在文件系统的独立暂存目录；tar 结束后仍读完压缩流，路径、身份、依赖头及解码检查全部成功后才提交到不存在的最终目录，不要求两遍解码。可处理失败只清理本次下载和暂存，不删除成功包或用户输入；异常退出留下的暂存名称不是合法最终槽，下次不读取或自动恢复，可由用户在确认路径后移除。写入或提交权限不足即报告该路径失败，不预检全部权限、不换根或回退来源；完整已有包不要求其目录可写，工作与结果位置仍须可写。

### 职责与交付次序

builder 拥有声明解析、包内直接依赖生成、暂存修正和本地归档，不认识 GitHub、CI 身份或发布策略。importer 拥有消费查找、依赖遍历、下载、校验和安全准备。CMake 入口拥有最小工具引导和全部包就绪后的 target 加载。独立 CI 程序拥有生产缓存判断和发布，workflow 拥有机器、环境、权限与运行并发；三个工具继续独立源码、独立可执行入口，通过 CLI 协作。

受影响工作依次为本地无清单打包与消费、CI 无全局清单发布、远端消费，分别验收后再规划下一阶段。本地阶段已完成，CI 的调用、缓存、发布接线及真实三平台供给和缓存复用均完成验证；远端消费尚未实施。CI 仍是独立系统，HTTPS 消费不因本设计确认便自动加入 CI 实施范围。新协议不预建旧发行资产迁移、历史接口兼容或远端清理。

本地阶段完成 builder 四行包头及单归档校验、importer 本地目录与归档查找和依赖闭包、CMake 新参数接线，并迁移本地生产、消费夹具及指南；它不增加 GitHub 消费。入口提供 `REMOTE_ROOT`/`--remote-root` 参数位置，但非空值明确报告远端消费尚未启用，不静默忽略或进行任何网络请求。CI 已同步迁移 `src/autolib-ci/` 的 prepare 调用、发行就绪判断和相应测试，以资产事实代替生产缓存的全局元数据并实现发布编排，不增加兼容层或临时清单。远端阶段才启用消费者的 Release 枚举与下载；CI 的本地测试不代替真实供给验收。

各阶段必须共用固定资产名、四行包头和平台身份：本地阶段以真实 builder 产物证明仅请求 flann 可消费 lz4、flann，并验证 queue-any-any；CI 阶段在获授权后三平台发布实际资产，核对名称、状态、API digest、实际字节及本地消费，不能只证明上传命令返回成功。远端阶段在该供给验收后，证明真实 Release 的分页读取、摘要和 HTTPS 重定向下载、引导执行及消费；fixture 覆盖异常响应，不为制造重名或分页额外污染正式 Release。

## 备选方案

**保留共享可变发行清单并增加备份或恢复。** 能保留原有消费者接口，但独立包发布仍依赖全局元数据提交；本方案直接使用资产事实和包内依赖，不增加全局恢复协议。

**保留不可变历史产物并选择版本组合。** 可以避免覆盖，但需要版本选择、依赖组合和存储清理；当前只支持一个当前槽，不引入版本管理。

**要求本地输入只能是归档或只能是已解包目录。** 会限制已有使用方式；固定顺序可以同时支持两者，无需为输入形态增加公开模式开关。

**要求用户另取 `.sha256` 文件。** 能提供独立的意外损坏对照，但人工搬运容易漏文件；已有压缩格式的内容校验随单归档交付，不增加第二次下载动作。

**包内存放整个归档的 SHA256 或以摘要作为签名。** 前者使生成过程自引用；后者不能认证来源。需要独立发布者认证时应另行设计可信依据，而不是扩大当前损坏检测承诺。

## 验收标准

- 只请求 flann 即准备并导入 lz4、flann；多根共享依赖 fixture 核对上述确定结果与逐包获取次数，环检测后不重复获取活动节点或继续后续根。缺失、重复替位或错序字段、非法依赖列表、大小写名称碰撞、Windows 保留名及错平台失败；合法重复依赖去重。消费者不读取生产模块声明或全局包清单。
- 小型 fixture 验证本地目录优先、本地归档次之、缺失时远端补齐；省略本地跳过本地来源，省略远端时完整路径及缺包路径都没有网络请求。已存在但损坏或错平台的候选不得被静默跳过。
- 本地单包首次准备只需该 tar.zst，不额外要求 `manifest.json` 或 `.sha256`。定向检查真实 builder 编码帧带内容校验；现有解码入口以正常、内容损坏及截断归档验证失败不提交、暂存清理及成功包保留，无校验帧按上述接受范围验证一次，不自建格式合规测试集。
- 本地依赖闭包齐全时重复消费不查询远端；需要远端时同一次 configure 的入口及 importer 共用一轮含分页的资产枚举，通过请求计数区分一次枚举与多个分页。fixture 定向覆盖重复候选、非 uploaded 状态、摘要缺失或非法、枚举后删除、摘要不匹配及 HTTPS 降级；失败无自动重枚举、不加载旧结果。真实下载与引导证据属于远端阶段。
- any/any 包在两个目标平台目录中正常复用；半通用身份、当前查找层通用与目标平台归档共存及机器码错平台均失败。有效目录遮蔽坏归档，坏目录不回退好归档，坏归档不回退远端；用少量定向组合覆盖，不穷举全部错误矩阵，不扩大发行平台集合。
- 重复 include、多次同输入导入和同进程切换来源或目标由真实 CMake fixture 覆盖；失败不加载旧结果，不承诺 target 回滚。旧 CLI/CMake 参数被拒绝，现有活动调用点及指南随所属阶段更新，历史基线与失败证据不改写。
- 保留安全解包、本地数据保护、真实依赖链接及搬迁运行验证；局部及阶段末验证只覆盖受影响增量，全部受影响阶段完成后执行一次全量回归。远端实机验证仍需明确授权，不以协议 fixture 冒充真实 Release 结果。

## 风险

本地可信目录及本地工具不接受独立来源认证，Zstd 内容校验也不能防恶意替换。远端 SHA256 只证明下载字节与所信任来源的记录一致，不证明整个来源未被替换。单个固定槽的删除、上传空窗仍会使缺包消费者失败，显式重跑可重新获取，不承诺持续可用或自动回滚。

包内依赖解决名称闭包，不解决多版本、ABI 变体或跨批次兼容。本地已有包不会自动追随远端更新，更新归档也不会覆盖已解包目录。已有包完整时可以只读复用；缺包时需要向显式本地根写入，权限不足即失败。不满足约定布局的任意安装树不能直接当作包缓存使用。

刷新单包时，用户先保护本地修改，再移走 `LOCAL_ROOT/packages/<目标OS>-<目标架构>/<包名>/`；不因该包有依赖而删除其他目录。再次导入可复用其他已有依赖，并按相同优先级获取该包；本地归档仍存在时会优先于远端，欲改用远端还需移走本包对应归档。此操作不影响其他平台的通用包副本，也不承诺刷新整个闭包为同一发布批次。
