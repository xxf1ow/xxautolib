# Agent Note: 按名称消费与固定槽二进制交付

Status: proposed

## 问题

本地安装树可用不代表归档能搬迁或被下游正确链接。将生产版本、缓存身份和安装布局全部暴露给下游，会增加选择规则；在消费端修复任意导入 target 的属性，又容易误改系统和 SDK 路径。

## 方案

沿用按名称消费、固定槽发布和生产端可搬迁保证，作为后续交付约束；本仓库尚未实现消费者、adapter、打包、缓存或发布。接入顺序由[路线图](../../../roadmap.md)拥有，当前本地安装不以完成本记录为验收前提。

### 职责与接口

模块定义及专用导入 adapter 同归 `src/dependencies/<模块名>/`。只有显式提供 adapter 的模块进入二进制交付；没有 adapter 的模块仍可本地构建。通用构建层不依赖 CI 或发布脚本；未来 CI 负责规划和调用，产物层负责暂存、打包、发布与镜像，消费者只获取并导入包，不调用生产端流水线。具体新增路径在对应实现批次确认，不先建空目录。

下游只按包名请求，通用入口保留小型 bootstrap 与固定 core 的划分，通过全局 Imported Target `AutoLib::<name>` 提供链接接口。生产版本是构建输入，build ID 是内部缓存身份；两者都不进入下游坐标。不提供版本、签名、历史、variant、component 或自动依赖闭包选择。调用者列出全部所需包，core 先获取这些包再加载 adapter，adapter 不偷偷下载依赖。

同一包只有一个当前 `(name, os, arch)` 槽，不并存 CRT、工具集或功能变体。需要同时分发不兼容 ABI 时必须另行设计，不能把差异藏进包名或 build ID。架构内部值统一 `x86_64`、`aarch64`，在入口归一明确别名，拒绝模糊或不支持值；平台无关包是[CI 方向](../process/2026-10-20-native-platform-ci.md)中的显式扩展，不是机器码包的回退规则。

### 本地状态与获取

已有 core 和匹配平台的本地包目录是消费端权威，不联网比较或自动覆盖。刷新由用户显式移除需要更新的本地包；错平台本地包报错，不自动换包。此规则属于未来二进制消费，不代替当前源码构建的 stamp 机制。

缺包时，每次 configure 至多读取一次 manifest，严格选择唯一匹配行，按摘要校验字节，在受控临时目录解压。归档必须只有一个与包名一致的顶层目录，并带包内 `autolib-import.cmake`；检查完成后才移入最终目录，成功清理自身临时状态。失败后重跑只丢弃该次获取的临时目录，不覆盖已有最终包，不增加持久化恢复数据库。入口、manifest 和 adapter 中的包名及平台身份须一致。

### 可搬迁安装与导入

打包复制安装树到 staging，只修正暂存副本，不修改原 `3rdparty/`。只处理已知 CMake/pkg-config 元数据形式及精确生产前缀，保留合法系统和 SDK 绝对路径；发现未处理的生产路径须失败。保留上游安装布局，不为所有包搬动 Config 或库文件。

每个 adapter 显式选一种真实机制：唯一精确 Config、唯一精确 `.pc`、固定 include 根或精确 raw-library 名。只在本包或明确声明的 sibling 包中定位；缺失、多个匹配、越出允许目录或意外 target 均失败，不回退系统，不扫描任意 Config 猜入口，也不按 OS 或安装布局分支猜路径。

包内导入文件统一保存包身份与平台并挂接实际 target，不另存一份重复身份的 BUILDINFO。Boost 的 `find_dependency(ZLIB)` 必须绑定 sibling 包内静态 zlib，不能以系统动态 zlib 通过验证；最低 CMake 仍为 3.20，不依赖更高版本新增的静态库查找开关。

### 缓存与发布

公开 manifest 每行严格只有 `name`、`os`、`arch`、`asset`、`sha256`，每个当前槽唯一；不加入 URL、版本、build ID、依赖或历史。asset 为权威字段，消费者不重建文件名。资产使用固定名，发布先替换资产，完成校验后最后发布 manifest。观察到不同代际字节时摘要检查失败，等待发布完成后重跑；不承诺跨资产原子发布，摘要不等于发布者认证。

build ID 只供生产缓存使用。输入覆盖本模块定义、版本、补丁及专用构建文件、adapter、传递构建依赖的版本及构建输入和共享生产代码；依赖的 adapter 独立变化不传播到使用方。迁移时适配 TOML 与文件引用，不照搬只覆盖旧单文件模块的输入列表。内部 ID 不进公开 manifest、文件名或下游 API。

缓存命中须同时核对当前 manifest、固定资产、私有 build ID、GitHub digest、实际下载字节和归档身份/adapter；强制重建替换该槽。枚举 Release 时读取全部分页，下载使用资产 ID，不从资产文件名推断完整状态。来源候选去重后各尝试一次，不叠加多层无限重试。

GitHub 是发布状态与摘要来源，Gitee 镜像同样使用 manifest 校验。镜像先同步资产再更新 manifest，已有同名资产替换失败保留或恢复该槽旧字节，方便显式重跑。目标 Release 仅在 404 或成功响应为 JSON null 时初始化，认证、网络及其他错误不能误当不存在。凭据只经环境或无回显临时输入提供，不缓存到仓库文件。

只有默认分支可以发布或更新镜像，脚本自身也校验，不能只依赖 workflow 条件。相同分支的新构建可取消旧构建；镜像使用独立串行队列，不中途取消固定名替换。镜像可在 finalize 成功后调用，或显式重试已发布状态，不因任意 push 自动启动。新仓库的发布地址、账户和远端写操作须另行授权，不沿用既有仓库地址或凭据。

## 备选方案

**按版本、签名或 build ID 消费并保留历史。** 会增加槽位、默认选择、回滚与清理协议；当前需求只取当前包，回滚通过重新发布期望字节完成。

**消费端遍历并改写 target 属性。** 消费者缺少生产布局信息，容易误改合法绝对路径；可搬迁性在暂存打包阶段保证。

**通用扫描器自动识别任意 Config 或库。** 可能选中内嵌依赖或错误静动态变体；adapter 声明精确身份并对歧义失败。

**用 FetchContent 获取二进制包。** 引入额外子构建和持久 stamp；直接获取、校验、解压和保留本地目录足以满足该消费生命周期。

## 验收标准

- 代表包在不同安装布局及搬迁前缀下通过真实链接；缺失、歧义、包外路径和系统库替代均失败，原安装树保持不变。
- 小型 fixture 验证本地复用、错平台拒绝、严格五字段与唯一槽、摘要错误、失败临时状态重跑及所请求包先获取后导入。
- 缓存全命中、部分缺失、输入变化和强制重建符合内部 ID 及固定槽规则；生产和消费平台身份一致。
- 分页、发布顺序、缺失 Release、镜像失败重跑和非默认分支禁止写入由本地协议 fixture 覆盖；获授权后再以真实远端验证，不能用本地 fixture 冒充。

## 风险

固定槽不保留可选择的历史，错误发布影响后续新消费者；已有本地目录保持原字节，须显式刷新。摘要只检查内容一致性，不认证发布者。平台与包名不能表达多 ABI 并存，这一限制不能靠自动覆盖隐藏。参考已有八包适配不代表本仓库须首批同时迁移八包，也不代表其他模块天然可搬迁。
