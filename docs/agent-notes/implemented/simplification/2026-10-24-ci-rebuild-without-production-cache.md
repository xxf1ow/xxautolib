# Agent Note: CI 每轮重建与文件名发布

Status: implemented

## 问题

首期 queue、lz4、flann 构建较快。跨运行复用 Release 包仍需下载、校验、解包、恢复安装树及消费验证，节省的编译成本不足以支撑独立输入身份、缓存失效和恢复路径。资产 label 中的 JSON 还覆盖 GitHub 下载列表的文件名，妨碍人工选择包。

## 决定

CI 每轮在该运行与平台的隔离安装根中，按依赖先序构建所选模块的完整依赖闭包。同轮共享依赖只构建一次，后续层使用已安装的依赖；不从 Release 下载包恢复安装树，不复用其他运行的生产包或工作区原有安装 sentinel。源码、工具和 Go 下载缓存保持各自原有规则。

删除生产 build ID、逐包生产提交、缓存命中结果和 force 输入，不新增包内生产元数据、sidecar、Actions 包缓存或发行清单。整个运行的提交、run ID 和 attempt 仍用于授权与结果归属，不能随缓存字段删除。

发布沿用固定文件名、唯一通用包 publisher、逐槽消费验证、实际 SHA256、权限检查和同名替换。上传不设置 label，并要求响应 label 为空；GitHub 下载列表显示文件名。失败保留已经上传的其他槽，显式重跑重新构建本次所选闭包，不补写历史运行结果或自动回滚。

本记录部分替代 [CI 系统设计](../architecture/2026-10-20-ci-system.md)中的生产缓存、身份和重跑复用决定，以及[固定槽交付设计](../../proposed/architecture/2026-10-20-name-only-artifact-delivery.md)中的生产缓存要求；其他职责、环境、消费和发布约束继续由原记录拥有。

## 备选方案

**保留 Release 生产缓存。** 原动机是避免重复编译和复用失败运行中的成功产物，但当前代表集收益有限。把 build ID 搬入压缩包需要修改打包协议，并不能去掉下载、解包和恢复成本；给 label 加文件名仍保留冗长展示，均不采用。

**改用 Actions 包缓存。** 仍需维护输入身份与命中分支，只改变存储位置；本次直接放弃跨运行生产包复用，不替换缓存后端。

## 影响

重跑会重新编译所选包和依赖，后续耗时库的构建成本可能增加。仅在真实编译成本成为瓶颈时另行评估缓存，不预建接口。消费者本地包复用、归档内容校验、GitHub 摘要和既有包格式不变，builder 与 importer 生产代码不变。

定向回归覆盖无 label 同名替换、拒绝 force 参数、隔离安装根、同轮依赖顺序与单次构建；真实 Windows 小型依赖夹具在已有发布资产的第二轮仍重新编译依赖并链接运行。上传摘要或展示字段不符、非法分支引用、失败前置层和缺失汇总记录仍失败；分支授权见[importer 分发与分支发布设计](../../proposed/architecture/2026-10-27-importer-distribution-and-branch-release.md)。

本地代码修改不改变已有远端资产；部署后发布选中槽才以空 label 替换。真实 GitHub 页面和新流程的三平台远端验收须在获授权运行后确认，既有缓存命中记录不作为本次重建策略的验证证据。
